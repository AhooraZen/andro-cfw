## 🎯 این لایبری چی کار می‌کنه؟

توی کشوری مثل ایران که `api.telegram.org` فیلتر شده، توسعه‌دهنده‌ها برای اجرای ربات‌هاشون یا باید VPN استفاده کنن یا سرور خارجی بگیرن.

**andro-cfw** این مشکل رو با یه ترفند حل می‌کنه: یه Cloudflare Worker به عنوان reverse proxy بین ربات و تلگرام قرار می‌ده:

```
ربات شما (پایتون / JS / PHP)  ←→  Cloudflare Worker (غیرفیلتر)  ←→  api.telegram.org
```

شبکه‌ی Edge کلادفلر از ایران قابل دسترسه، پس ربات شما به Worker وصل میشه و Worker به تلگرام.

اگه چند اکانت کلادفلر داشته باشید، یه دیمن محلی مشترک وسط کار می‌ایسته و سالم‌ترین ورکر رو براتون انتخاب می‌کنه:

```
ربات ۱ ┐
ربات ۲ ┼→  دیمن andro-cfw (روی 127.0.0.1)  →  ورکر ۱ / ۲ / ۳  →  api.telegram.org
ربات ۳ ┘        شمارش + مسیریابی + تلاش مجدد
```

## ✨ ویژگی‌ها

- 🔒 **بدون نیاز به VPN** — نه روی سیستم شما، نه روی سرور و نه هنگام تنظیم وب‌هوک.
- 🐍 **نصب کاملاً پایتونی** — کل نصب همون `pip install andro-cfw` است. دپلوی مستقیم با REST API کلادفلر انجام می‌شود، پس نه نصب زنجیره‌ابزار جاوااسکریپت لازم است، نه اجرای پکیج‌منیجر سیستم و نه هیچ چیزی که `sudo` بخواهد.
- ☁️ **میزبانی ۱۰۰٪ سرورلس ابری** — اجرای ۲۴ ساعته ربات‌های واقعی مستقیماً رو لبه‌ی کلادفلر (بدون نیاز به روشن بودن لپ‌تاپ یا سرور).
- 🧠 **دیمن پروکسی مشترک (`andro-cfw daemon`)** — یک پروکسی محلی همیشه‌روشن که همه ربات‌های سیستم از آن استفاده می‌کنند، به‌جای یک لودبالانسر جدا داخل هر پروسه.
- 📈 **شمارش دقیق سهمیه** — چون دیمن خودش همه درخواست‌ها را پروکسی می‌کند، آن‌ها را می‌شمارد و **قبل از** رسیدن به سقف ۱۰۰٬۰۰۰ درخواست روزانه اکانت را عوض می‌کند، نه بعد از خوردن به خطای 429.
- 📊 **داشبورد محلی** — سلامت ورکرها، مصرف سهمیه هر اکانت، نمودار تاخیر و لاگ سوییچ‌ها روی `http://127.0.0.1:8787/__andro/`.
- 🐍 **پتچر تک‌خطی خودکار (`andro_cfw.patch()`)** — شناسایی و پتچ خودکار فریم‌ورک‌های HTTP Bot API: `telebot`، `python-telegram-bot` و `aiogram`. (کلاینت‌های MTProto مثل pyrogram/hydrogram/telethon از پروکسی HTTP رد نمی‌شوند و `patch()` هشدار می‌دهد.)
- 🔀 **لود بالانس چند اکانته** — ادغام سهمیه رایگان چندین اکانت کلادفلر (۱۰۰ هزار درخواست در روز برای هر اکانت) با مسیریابی بر اساس تاخیر و ریست خودکار روزانه.
- ⚡ **ساخت کد و وب‌هوک خودکار (`andro-cfw serverless`)** — دپلوی ۱-دستوری ربات‌های سرورلس با پرسش‌وپاسخ هوشمند.
- 🔍 **تست پینگ و سلامت ورکر (`andro-cfw check`)** — بررسی زنده سرعت پاسخ‌دهی (Keep-Alive) و کد وضعیت HTTP ورکرها.
- 🔐 **ذخیره‌سازی رمزنگاری‌شده** — هم فایل سشن و هم توکن API کلادفلر با Fernet (AES-128 + HMAC) رمزنگاری می‌شوند.

## 🔑 قدم اول: ورود با توکن API کلادفلر (`andro-cfw login`)

احراز هویت با یک **توکن API** محدود انجام می‌شود که فقط یک بار می‌سازید:

۱. آدرس [`https://dash.cloudflare.com/profile/api-tokens`](https://dash.cloudflare.com/profile/api-tokens) را باز کنید.
۲. روی **Create Token** بزنید، قالب آماده‌ی **«Edit Cloudflare Workers»** را انتخاب کنید و تا **Create Token** ادامه بدهید.
۳. توکن را کپی کنید (کلادفلر فقط همان یک بار نشانش می‌دهد) و بعد:

```bash
andro-cfw login
```

توکن را در پرامپت مخفی جای‌گذاری کنید. برنامه اول اعتبار توکن را از خود کلادفلر می‌پرسد، شناسه اکانت را پیدا می‌کند و بعد آن را رمزنگاری‌شده با Fernet — همان کلید محلی که از `cfw.session` محافظت می‌کند — در `~/.andro_cfw/credentials` با دسترسی `0600` ذخیره می‌کند.

آن قالب دقیقاً همان دسترسی لازم (`Workers Scripts:Edit`) را می‌دهد و نه بیشتر. اگر توکن شما به چند اکانت کلادفلر دسترسی داشته باشد، برنامه به‌جای حدس زدن، لیست‌شان را نشان می‌دهد تا با `--account-id` یکی را انتخاب کنید.

## 🚀 قدم دوم: دپلوی ورکر (`andro-cfw init`)

```bash
andro-cfw init                 # یک اکانت، یک ورکر
andro-cfw init --accounts 3    # استخر لودبالانس‌شده روی سه اکانت
```

کد ورکر مستقیماً به API کلادفلر آپلود می‌شود، مسیر `workers.dev` فعال می‌شود و آدرس نهایی داخل فایل رمزنگاری‌شده `cfw.session` در پوشه پروژه ذخیره می‌شود.

### دو راه برای احراز هویت

| | `andro-cfw login` | `andro-cfw login --browser` |
|---|---|---|
| چی می‌دی | توکنی که خودت می‌سازی و پیست می‌کنی | هیچی — روی سایت خود کلادفلر تأیید می‌کنی |
| چی ذخیره می‌شه | همون توکن، تا وقتی باطلش کنی | توکن کوتاه‌مدت که خودکار تازه می‌شه |
| روی سرور بدون مرورگر | آره (`$CLOUDFLARE_API_TOKEN`) | نه، مرورگر لازم داره |
| راه‌اندازی | ندارد | نیاز به ثبت کلاینت OAuth دارد |

روش توکن پیش‌فرضه چون راه‌اندازی نمی‌خواد و روی سرور هم کار می‌کنه. روش مرورگری
اعتماد کمتری ازت می‌خواد: اعتبارنامه روی دامنه‌ی خود کلادفلر صادر می‌شه، صفحه‌ی
رضایت دقیقاً می‌گه چه دسترسی‌هایی داده می‌شه، و چیزی که روی دیسک می‌شینه منقضی می‌شه.

**فعال کردن روش مرورگری.** پروژه عمداً هیچ شناسه‌ی OAuth از خودش ندارد. یک کلاینت
عمومی با «Authorization Code with PKCE» و آدرس بازگشت
`http://localhost:8976/oauth/callback` ثبت کن
([راهنمای کلادفلر](https://developers.cloudflare.com/fundamentals/oauth/create-an-oauth-client/))
و بعد `ANDRO_CFW_OAUTH_CLIENT_ID` را ست کن.

> **چرا شناسه‌ی رنگلر را کپی نمی‌کنیم؟** عمومیه و کار هم می‌کرد. ولی صفحه‌ی رضایت
> کلادفلر اسم برنامه‌ای که اجازه می‌گیره را نشون می‌ده — یعنی به کاربر گفته می‌شد
> *Wrangler* دسترسی می‌خواد، و اون مجوز هم زیر اسم رنگلر توی لیست برنامه‌های مجاز
> کاربر ثبت می‌شد. این از توکن خواستن بدتره، پس این کار انجام نشده.

در هر دو حالت اعتبارنامه‌ها رمزنگاری‌شده در `~/.andro_cfw/credentials` (دسترسی 0600)
با همان کلید محلی نشست ذخیره می‌شن، و `andro-cfw logout` باطل و پاکشون می‌کنه.

## 🧠 دیمن پروکسی مشترک (`andro-cfw daemon`)

روی هر سیستم فقط یک دیمن لازم است:

```bash
andro-cfw daemon
```

فقط روی `127.0.0.1` گوش می‌دهد و هر رباتی که بعد از آن بالا بیاورید از همان رد می‌شود؛ یعنی `andro_cfw.patch()` و `CFWSession` خودشان دیمن را پیدا می‌کنند و دیگر داخل هر پروسه یک لودبالانسر جدا بالا نمی‌آید.

**چرا لودبالانسر داخل‌پروسه‌ای حذف شد؟** قبلاً هر ربات لودبالانسر خودش را می‌ساخت. سه ربات یعنی سه لودبالانس مستقل: هرکدام جداگانه می‌فهمید که اکانت به خطای 429 خورده، هر سه روی یک فایل سشن می‌نوشتند و هیچ‌کدام خبر نداشت بقیه چقدر از سهمیه را سوزانده‌اند. اصلاً شمارش درخواستی در کار نبود و سوییچ کاملاً واکنشی بود، پس **هر بار جابه‌جایی، هزینه‌اش یک درخواست شکست‌خورده بود**.

حالا چون دیمن خودش همه درخواست‌ها را پروکسی می‌کند، می‌تواند ساده بشماردشان:

- **شمارش واقعی، نه حدس.** تعداد درخواست هر اکانت در هر روز UTC داخل یک دیتابیس SQLite در `~/.andro_cfw/usage.db` نگه‌داری می‌شود.
- **سوییچ زودهنگام.** هر اکانت وقتی به **۹۵٪** سقف ۱۰۰٬۰۰۰ درخواست روزانه پلن رایگان برسد کنار گذاشته می‌شود، پس ربات شما اصلاً آن 429 را نمی‌بیند.
- **انتخاب بر اساس تاخیر.** بین ورکرهای سالم، آن‌که **میانه‌ی** تاخیرش کمترین است انتخاب می‌شود (میانه، نه میانگین: یک تایم‌اوت ۳۰ ثانیه‌ای نباید یک اکانت سالم را از دور خارج کند) — نه صرفاً کوچک‌ترین ایندکس.
- **تلاش مجدد روی خطاهای گذرا.** جواب 5xx از لبه با فاصله‌ی فزاینده دوباره امتحان می‌شود، به‌جای اینکه به‌عنوان خطا تحویل ربات شود.
- **یک منبع حقیقت.** همه ربات‌های سیستم یک مجموعه شمارنده، یک تصویر از سلامت ورکرها و یک تصمیم سوییچ مشترک دارند.

### ⚠️ این شمارنده‌ها چه چیزی را نمی‌بینند

**ترافیک وب‌هوک از تلگرام مستقیم به ورکر می‌رود و اصلاً از دیمن رد نمی‌شود.** هیچ چیزی روی سیستم شما آن درخواست‌ها را نمی‌بیند، پس شمردنشان ممکن نیست.

بنابراین اعداد داشبورد فقط شامل **لانگ‌پولینگ و فراخوانی‌های خروجی Bot API** است. اگر ربات شما وب‌هوکی است، انتظار داشته باشید عدد گزارش‌شده کم — گاهی نزدیک صفر — باشد در حالی که مصرف واقعی‌تان روی کلادفلر خیلی بیشتر است. در آن حالت عدد معتبر را باید از داشبورد خود کلادفلر بگیرید.

## 📊 داشبورد محلی

تا وقتی دیمن روشن است، این آدرس را باز کنید:

```
http://127.0.0.1:8787/__andro/
```

آدرس موقع بالا آمدن دیمن چاپ می‌شود؛ پورت پیش‌فرض `8787` است و با `--port` عوض می‌شود. صفحه را خود دیمن سرو می‌کند — یک HTML ساده بدون هیچ فایل بیرونی، فقط روی لوکال‌هاست — و اینها را نشان می‌دهد:

- **سلامت ورکرها** — کدام اکانت‌ها بالا هستند و کدام‌ها فعلاً کنار گذاشته شده‌اند.
- **مصرف سهمیه هر اکانت** — تعداد درخواست شمرده‌شده امروز در برابر سقف ۱۰۰٬۰۰۰ تایی.
- **نمودار تاخیر** — میانه زمان پاسخ هر ورکر در بازه اخیر.
- **لاگ رویدادها** — هر سوییچ، هر رسیدن به سقف سهمیه و هر تلاش مجدد ناموفق، همراه با زمان.

همین لاگ رویدادها را در ترمینال هم می‌شود با `andro-cfw logs` دید.

## 📖 راهنمای کامل: اجرای ۱۰۰٪ سرورلس ربات‌های تلگرام روی کلادفلر

شما می‌توانید ربات تلگرام خودتون رو **۱۰۰٪ سرورلس** روی Cloudflare Edge با **آپتایم ۲۴ ساعته**، **تاخیر پاسخ‌دهی ۵ میلی‌ثانیه** و **هزینه صفر** (با استفاده از پلن رایگان ۱۰۰،۰۰۰ درخواست در روز کلادفلر) اجرا کنید.

---

### روش اول: دپلوی ۱-دستوری وب‌هوک سرورلس (`andro-cfw serverless`)

تلگرام را به ورکر خودتان وصل کنید و هر آپدیت را به بک‌اند خودتان برسانید:

۱. **دستور دپلوی رو بزنید**:
   ```bash
   andro-cfw serverless --forward-url https://your-backend.example.com/telegram
   ```
۲. **توکن ربات** را وارد کنید (به ترتیب اولویت):
   - متغیر محیطی `TELEGRAM_BOT_TOKEN`،
   - پرامپت مخفی (ورودی روی صفحه چاپ نمی‌شود)،
   - `--token` (کم‌ترین اولویت: آرگومان‌های خط فرمان برای همه پروسه‌های سیستم قابل خواندن است).
۳. **تمام!** توکن به‌صورت Secret رمزنگاری‌شده روی ورکر ذخیره می‌شود، یک secret تازه برای
   وب‌هوک ساخته می‌شود و وب‌هوک **بدون نیاز به VPN** روی تلگرام ست می‌شود.

#### امنیت وب‌هوک

| | |
|---|---|
| توکن ربات | روی HTTPS به‌عنوان Secret رمزنگاری‌شده ورکر (`BOT_TOKEN`) آپلود می‌شود. هرگز داخل URL وب‌هوک قرار نمی‌گیرد. |
| احراز هویت وب‌هوک | یک secret ۳۲ بایتی به `setWebhook(secret_token=...)` داده می‌شود؛ تلگرام آن را در هدر `X-Telegram-Bot-Api-Secret-Token` برمی‌گرداند و ورکر هر آپدیت بدون این مقدار را رد می‌کند. |
| CORS | به‌صورت پیش‌فرض خاموش است. فقط اگر مرورگر باید ورکر را صدا بزند `ALLOWED_ORIGINS` را ست کنید. |

> **از نسخه v0.3.x ارتقا می‌دهید؟** نسخه‌های قبلی توکن ربات را به شکل `?token=...` داخل
> URL وب‌هوک می‌گذاشتند. آن URL توسط تلگرام ذخیره و در هر آپدیت دوباره ارسال می‌شود.
> دستور `andro-cfw serverless` را دوباره اجرا کنید و **توکن قبلی را در @BotFather باطل کنید** —
> آن توکن را افشاشده در نظر بگیرید.

### روش دوم: کد کامل جاوااسکریپت برای ورکر اختصاصی

اگر می‌خواهید ربات سرورلس با منطق سفارشی، دکمه‌های شیشه‌ای یا پردازش اختصاصی بنویسید، کدش را به شکل یک ماژول ورکر بنویسید و از پنل کلادفلر (**Workers & Pages** ← ورکر خودتان ← **Edit code**) جایگزین کنید.

قالبی که همراه پکیج می‌آید `worker.mjs` است: جاوااسکریپت خالص به شکل ES module. مسیر آپلود کلادفلر هیچ باندلری ندارد، پس هر چیزی که ورکر اجرا می‌کند باید از قبل جاوااسکریپت معتبر باشد؛ اگر با TypeScript راحت‌ترید، باید اول کامپایلش کنید.

#### کد `worker.mjs`:

```javascript
const TELEGRAM_ORIGIN = "https://api.telegram.org";

export default {
  async fetch(request, env) {
    const url = new URL(request.url);

    // ۱. پردازش وب‌هوک تلگرام (POST /webhook)
    if (request.method === "POST" && url.pathname.includes("/webhook")) {
      try {
        // توکن فقط از Secret ورکر خوانده می‌شود، نه از درخواست
        const token = env.BOT_TOKEN;
        const update = await request.json();

        if (update && update.message && update.message.text && token) {
          const chatId = update.message.chat.id;
          const text = update.message.text.trim();

          let replyText = "";

          // منطق دستورات سفارشی ربات
          if (text === "/start") {
            replyText = "👋 سلام! این ربات ۱۰۰٪ سرورلس روی Cloudflare Edge اجرا می‌شه!";
          } else if (text === "/ping") {
            replyText = "🏓 پینگ از ورکر کلادفلر!";
          } else if (text.startsWith("/echo ")) {
            replyText = `📢 متن شما: ${text.slice(6)}`;
          } else {
            replyText = `🤖 پیام شما دریافت شد: "${text}"`;
          }

          // ارسال پاسخ به تلگرام
          const replyUrl = `${TELEGRAM_ORIGIN}/bot${token}/sendMessage`;
          await fetch(replyUrl, {
            method: "POST",
            headers: { "Content-Type": "application/json" },
            body: JSON.stringify({
              chat_id: chatId,
              text: replyText,
              parse_mode: "Markdown",
            }),
          });
        }
      } catch (err) {
        console.error("Webhook processing error:", err);
      }
      return new Response("OK", { status: 200 });
    }

    // ۲. پروکسی معکوس شفاف برای ربات‌های پایتون/سیستم محلی
    const targetUrl = TELEGRAM_ORIGIN + url.pathname + url.search;
    return fetch(targetUrl, {
      method: request.method,
      headers: request.headers,
      body: ["GET", "HEAD"].includes(request.method) ? undefined : request.body,
      duplex: "half",
    });
  },
};
```

### روش سوم: ربات پایتون با پتچر تک‌خطی (`andro_cfw.patch()`)

اگر ترجیح می‌دید رباتتون رو با پایتون (telebot, aiogram, ptb) بنویسید:

```python
import telebot
import andro_cfw

# تنظیم خودکار پروکسی فقط با ۱ خط کد
session = andro_cfw.patch()

bot = telebot.TeleBot("YOUR_BOT_TOKEN_FROM_BOTFATHER")

@bot.message_handler(commands=["start", "help"])
def send_welcome(message):
    bot.reply_to(
        message,
        "🤖 **سلام از پشت فیلتر!**\n\n"
        f"🌐 **آدرس ورکر**: `{session.worker_url}`\n"
        "🔒 **وضعیت**: بدون فیلتر و بدون نیاز به VPN!"
    )

if __name__ == "__main__":
    print(f"🚀 ربات روی پروکسی ورکر روشن شد ({session.worker_url})...")
    bot.infinity_polling(timeout=20, long_polling_timeout=20)
```

اگر شمارش سهمیه، مسیریابی بر اساس تاخیر و داشبورد را می‌خواهید، اول `andro-cfw daemon` را بالا بیاورید؛ کد بالا در هر دو حالت یکسان است.

### روش چهارم: حالت هدایت وب‌هوک به PHP / هاست شخصی (`FORWARD_WEBHOOK_URL`)

اگر یک ربات PHP یا پایتون یا Go روی هاست سی‌پنل یا سرور شخصی خودتون دارید و فیلتر شده:

۱. ورکر را به بک‌اند خودتان وصل کنید. ساده‌ترین راه این است که موقع دپلوی خود
   برنامه این Secret را برایتان ست کند:
   ```bash
   andro-cfw serverless --forward-url https://your-server.com/my_bot_webhook.php
   ```
   دستی هم می‌شود: مقدار `FORWARD_WEBHOOK_URL` را از پنل کلادفلر و از مسیر **Workers & Pages ← ورکر خودتان ← Settings ← Variables and Secrets** ست کنید.
۲. کلادفلر آپدیت‌های تلگرام رو می‌گیره، فیلترینگ رو دور می‌زنه و مستقیماً به هاست شما ارسال می‌کنه!

ورکر همیشه به تلگرام جواب `200 OK` می‌دهد، حتی وقتی بک‌اند شما بالا نیست — چون جواب غیر ۲۰۰ باعث می‌شود تلگرام همان آپدیت را بی‌نهایت بار دوباره بفرستد و یک قطعی کوتاه تبدیل به طوفان تلاش مجدد شود.

## 🛠 سرور Bot API اختصاصی (`UPSTREAM_API_ORIGIN`)

به‌صورت پیش‌فرض ورکر به `https://api.telegram.org` پروکسی می‌کند. اگر
[`telegram-bot-api`](https://github.com/tdlib/telegram-bot-api) خودتان را بالا آورده‌اید،
می‌توانید ورکر را به آن وصل کنید تا محدودیت ۵۰ مگابایتی آپلود تلگرام برداشته شود.

مقدار `UPSTREAM_API_ORIGIN` را از پنل کلادفلر و از مسیر **Workers & Pages ← ورکر خودتان ← Settings ← Variables and Secrets** ست کنید، مثلاً `https://bot-api.your-server.com`.

فقط origin استفاده می‌شود؛ هر path یا query داخل مقدار حذف می‌شود و مقدار نامعتبر یا
غیر http(s) به `api.telegram.org` برمی‌گردد تا ترافیک به جای ناخواسته نرود.

## 🔄 مهاجرت از نسخه ۰.۴.x

هر چیزی که قبلاً دپلوی کرده‌اید سر جایش است — ورکر روی کلادفلر از دید ربات شما فرقی نکرده و فایل `cfw.session` فعلی‌تان بدون تغییر خوانده می‌شود.

دو کار لازم است و یک چیز را هم می‌توانید پاک کنید:

۱. **دوباره لاگین کنید، این بار با توکن API.** روش قبلی (لاگین مرورگری) دیگر وجود ندارد.
   یک توکن با قالب **«Edit Cloudflare Workers»** از
   [`https://dash.cloudflare.com/profile/api-tokens`](https://dash.cloudflare.com/profile/api-tokens)
   بسازید و `andro-cfw login` را اجرا کنید (اگر چند اکانت دارید، برای هر کدام یک بار).
   تا وقتی این کار را نکنید، هر دستوری که به کلادفلر کار داشته باشد از شما لاگین می‌خواهد.
۲. **دیمن را بالا بیاورید.** دستور `andro-cfw daemon` شمارش سهمیه، سوییچ زودهنگام و
   داشبورد را به شما می‌دهد. بدون آن هم ربات‌ها کار می‌کنند، ولی مستقیم می‌روند و
   چیزی شمرده نمی‌شود.
۳. **دیگر خبری از نصب Node.js نیست.** اگر نسخه‌های قبلی این ابزار روی سیستم شما
   نودجی‌اس نصب کرده بودند، الان هیچ‌جای این پکیج به آن نیازی ندارد؛ اگر فقط
   به‌خاطر همین ابزار نصبش کرده بودید، می‌توانید حذفش کنید. متغیرهای محیطی `ANDRO_CFW_ALLOW_NODESOURCE` و `ANDRO_CFW_NO_AUTO_INSTALL` هم دیگر هیچ کاری نمی‌کنند و می‌شود از پروفایل شل حذفشان کرد.

کد ربات شما تغییری نمی‌کند: `andro_cfw.patch()`، `CFWSession` و کدهای تولیدشده با `snippet` همگی همان API قبلی را دارند.

## 🔐 نکات امنیتی

- **`cfw.session` رمزنگاری شده** — با Fernet (AES-128-CBC + HMAC). کلید توی `~/.andro_cfw/key` هست.
- **توکن کلادفلر هم رمزنگاری می‌شود** — داخل `~/.andro_cfw/credentials` با دسترسی `0600` و همان کلید. برای خروج کافی است همین فایل را پاک کنید.
- **از قالب «Edit Cloudflare Workers» استفاده کنید.** این قالب فقط `Workers Scripts:Edit` می‌دهد؛ یعنی توکن لو رفته به DNS، دامنه‌ها یا صورتحساب شما دسترسی ندارد.
- **گیت:** حتماً `cfw.session` رو به `.gitignore` اضافه کن.
- **هیچ چیزی با دسترسی روت نصب نمی‌شود.** این پکیج پایتون خالص است و فقط درخواست HTTPS می‌زند؛ نه پکیج‌منیجر سیستم را صدا می‌زند و نه `sudo` می‌خواهد.
- دیمن و داشبوردش فقط روی `127.0.0.1` گوش می‌دهند.
